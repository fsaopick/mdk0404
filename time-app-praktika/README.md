# Time App Praktika

Практическая работа выполнена на уровень "отлично".

Проект состоит из 4 контейнеров:

- `frontend` - интерфейс на Vue 3
- `api` - сервер на Express
- `mysql` - база данных MySQL 8
- `adminer` - веб-интерфейс для просмотра базы данных

## Что реализовано

1. Приложение `time-db` запускается внутри Docker через `docker compose`.
2. Собрано собственное приложение минимум из трех компонентов:
   - `frontend`
   - `api`
   - `mysql`
   - дополнительный сервис `adminer`
3. Данные времени сохраняются в базе и отображаются в интерфейсе.

## Архитектура

### `frontend`

Показывает текущее время, отправляет запросы в API и выводит сохраненные записи. В контейнере фронтэнд собирается через Vite и раздается через Nginx.

### `api`

Принимает HTTP-запросы, работает с базой данных и отдает JSON-ответы:

- `GET /times` - получить список сохраненных времен
- `POST /times` - сохранить новое время
- `DELETE /time/:id` - удалить запись
- `GET /health` - проверка, что API работает

### `mysql`

Хранит таблицу `times`. При старте API автоматически проверяет подключение и создает таблицу, если ее еще нет.

### `adminer`

Позволяет проверить содержимое базы через браузер.

## Запуск проекта

### 1. Проверка Docker

Команда:

```bash
docker --version
```

Что делает:

- показывает установленную версию Docker
- подтверждает, что Docker доступен в системе

Команда:

```bash
docker compose version
```

Что делает:

- показывает версию `docker compose`
- подтверждает, что можно запускать многоконтейнерное приложение

### 2. Сборка и запуск всех контейнеров

Команда:

```bash
docker compose up --build -d
```

Подробное объяснение:

- `docker compose` - инструмент для запуска нескольких связанных контейнеров
- `up` - создать и запустить сервисы из файла `docker-compose.yml`
- `--build` - предварительно пересобрать образы, чтобы Docker использовал актуальный код
- `-d` - запустить контейнеры в фоновом режиме, чтобы терминал не был занят

После выполнения команды будут запущены сервисы:

- `frontend` на `http://localhost:8080`
- `api` на `http://localhost:5555`
- `mysql` на порту `3307`
- `adminer` на `http://localhost:8081`

### 3. Проверка работающих контейнеров

Команда:

```bash
docker compose ps
```

Что делает:

- показывает список контейнеров текущего проекта
- позволяет убедиться, что все сервисы находятся в состоянии `running`

### 4. Просмотр логов

Команда:

```bash
docker compose logs -f
```

Что делает:

- `logs` выводит журналы всех сервисов
- `-f` означает "follow", то есть логи будут показываться в реальном времени

Эта команда полезна для проверки:

- успешного подключения API к MySQL
- старта Nginx и Express
- возможных ошибок контейнеров

### 5. Остановка проекта

Команда:

```bash
docker compose down
```

Что делает:

- останавливает контейнеры
- удаляет созданные контейнеры и сеть проекта
- том `mysql_data` остается сохраненным, поэтому данные базы не пропадут

Если нужно удалить еще и том с данными, используется команда:

```bash
docker compose down -v
```

Здесь параметр `-v` удаляет volumes, включая `mysql_data`.

## Компоненты файла `docker-compose.yml`

### `services`

Главный раздел, в котором перечислены все контейнеры приложения.

### `mysql`

- `image: mysql:8.4` - готовый официальный образ MySQL
- `environment` - переменные окружения для создания базы и пароля root
- `ports: 3307:3306` - проброс порта контейнера наружу
- `volumes` - сохранение данных между перезапусками
- `healthcheck` - проверка, что база реально успела стартовать

### `api`

- `build: ./api` - образ собирается из папки `api`
- `environment` - настройки подключения к базе
- `depends_on` - API ждет готовности MySQL
- `ports: 5555:5000` - внешний порт для запросов к серверу

### `frontend`

- `build: ./frontend` - фронтэнд собирается из папки `frontend`
- `ports: 8080:80` - сайт открывается в браузере на порту `8080`
- `depends_on` - фронтэнд запускается после API

### `adminer`

- `image: adminer:4.8.1` - готовый образ Adminer
- `ports: 8081:8080` - панель базы доступна в браузере

### `volumes`

Раздел `mysql_data` нужен для постоянного хранения данных MySQL. Даже после остановки контейнеров база не исчезает.

## Как проверить работу приложения

1. Открыть `http://localhost:8080`
2. Нажать кнопку сохранения времени
3. Убедиться, что запись появилась в списке
4. Открыть `http://localhost:8081`
5. Войти в Adminer:
   - система: `MySQL`
   - сервер: `mysql`
   - пользователь: `root`
   - пароль: `password`
   - база: `time_db`
6. Проверить таблицу `times`
